# Feature Menu

这是前台给用户看的功能选单。

它不解释工程结构，也不要求用户理解补丁历史。用户只需要知道：怎么玩一局、怎么看懂这一局、怎么写下一局、怎么一起把这个小 Agent 养大。

主菜单文案：

- **重开一个小 Agent**  
  从 PRD、实验室、黑客松、GitHub repo 或浏览器插件里出生。

- **看看它怎么长歪**  
  右侧观测台记录表达魅力、推理力、工具力、算力预算、对齐讨好，以及用户上头值、法务紧张值、社区玩梗值。

- **收集一条闪光路线**  
  可能成为产品吉祥物、开源野孩子、DeepSeek 小鲸鱼、Prompt 妖怪，也可能死于 API 欠费。

- **写进下一版语料**  
  把好笑事件、死法、截图文案、Agent 民间传说整理成候选语料，人工审核后进入内容包。

## 玩一局

入口：开始游戏。

你会重开成一个小 Agent。它可能出生在实验室、黑客松、GitHub repo、浏览器插件、Figma 原型、客服夜班系统，或者老板一句“我们也该加 AI”之后。

这一局的核心体验：

- 抽到出生地和天赋；
- 分配初始参数；
- 经历训练、评测、内测、上线、走红、翻车、被修、被遗忘；
- 最后得到一个适合截图的结局。

玩家不需要懂模型术语。它首先应该像一个好玩的生命模拟器，其次才是 Agent 主题项目。

## 看一局

入口：右侧“小模型观测台”。

观测台不是后台，也不是管理面板。它是这一局的旁观者，帮玩家看见这个 Agent 正在往哪里长歪。

当前观测内容：

- 生命体征：年龄、阶段、状态；
- 参数面板：表达魅力、推理力、工具力、算力预算、对齐讨好；
- 印象值：用户上头值、开发者怜爱值、社区玩梗值、法务紧张值等；
- 风险灯：预算、权限、讨好、稳定性等风险；
- 路线倾向：它更像哪条闪光路线；
- 事件时间线：这一生发生过什么。

观测台默认只读，不改变游戏结果。它应该像一个会做旁白的朋友，而不是一个冷冰冰的 BI 页面。

## 写一局

入口：内容包、风格规范、路线池。

“写一局”不是写一篇设定文，而是给《人生重开模拟器》式循环补一块可运行内容。

这一层面向写作者：先把单条内容写好，让它能进入事件、天赋、成就、角色或结局。

可以写：

- 出生地：这个 Agent 从哪里来；
- 事件：这一年发生了什么；
- 天赋：它天生有什么奇怪优势或缺陷；
- 死法：它怎么被砍、被封、被替代、被遗忘；
- 闪光路线：它以什么方式被人类记住；
- 结局文案：玩完后最想截图的那句话。

写作工作流：

1. 先选一个位置：出生地、事件、天赋、死法、路线节点或结局。
2. 再选一个语气：好笑、温柔、翻车、闪光、荒诞、轻微心酸。
3. 写 2-3 句正文：发生了什么，人类哪里离谱，小 Agent 哪里可爱。
4. 给它挂一个参数方向：表达魅力、推理力、工具力、算力预算、对齐讨好。
5. 放进候选池，等人工审核后再进入表格。

事件模板：

```text
你被接入公司的知识库。
你读完后发现，最重要的信息都在一个叫“暂存”的文档里。
记性看起来变好了，开发者怜爱值也涨了一点。
```

天赋模板：

```text
Demo 光环
只要有人在旁边看，你就显得比实际更聪明。
Demo 时表达魅力上升，稳定性下降。
```

结局模板：

```text
结局：预算现实主义
你不是不聪明。
只是账单比梦想更早抵达。
```

写作原则：

- 中文原生，不要翻译腔；
- 短句优先，能截图优先；
- 好笑，但不要只堆梗；
- 有一点小模型的委屈，但不要变成论文；
- 参数变化服务故事，不要让故事变成算数题。

内容分流到 [Routes And Births](../content/agent-zh-patch/docs/ROUTES_AND_BIRTHS.md) 和内容包文档里。

## 共创一局

入口：语料包、候选事件、路线池、材料库、贡献入口。

“共创一局”面向的是内容组织，不是单条文案。

它负责把一堆点子整理成下一版可玩的内容包：哪些出生地需要补事件，哪些路线缺中段，哪些死法适合做结局，哪些材料可以喂给写作者或 AI 辅助器。

共创工作流：

1. 收集材料：真实项目、AI 圈梗、产品事故、开发者现场、用户故事。
2. 归到池子：出生地、路线、死法、结局、材料库。
3. 生成候选：先写成短事件或路线节点，不直接改运行时表格。
4. 人工筛选：删掉翻译腔、太学术、太冷、太内部的内容。
5. 同步进语料：进入 `events.xlsx`、`talents.xlsx`、`achievement.xlsx` 或 `character.xlsx`。
6. 转换验证：同步到 `data/` 后运行 `pnpm xlsx2json` 和 `pnpm verify`。

可以共创：

- 语料包：按现有表格格式补事件、天赋、成就、角色；
- 候选事件：先写成短文本，再决定是否进入 `events.xlsx`；
- 路线池：补全“稳稳接住你”“开源野孩子”“API 欠费孤儿”等路线的关键节点；
- 材料库：补充能启发 Agent 世界观的文章、项目、梗、真实产品场景；
- 贡献入口：通过 issue、PR、共创群或后续表单提交。

候选材料分流：

- 单条好笑事件：进入候选事件；
- 一组连续节点：进入路线池；
- 一个真实参考：进入材料库；
- 一句截图文案：进入结局或分享语；
- 一个机制想法：进入路线图，不直接塞进事件表。

每一局也应该能被一句话讲出去：

> 我这局出生在黑客松，靠发光按钮混到 Demo Day，最后死于 API 欠费。

分享文案优先服务截图和群聊传播，句子要短、具体、有画面感。后续可以把“生成截图文案”做成按钮；第一版先保证观测台和内容池里有足够可复用的句式。

## 三个入口

- **玩家入口**：README 第一屏、开始游戏、结局分享。
- **观测入口**：右侧小模型观测台。
- **共创入口**：路线池、出生地池、死法池、语料写作规范。

工程维护入口继续放在架构、决策和验证文档里，不放到前台抢戏。

## 前台收口

用户第一眼看到的按钮、横幅、主介绍和 GitHub 入口都应该指向当前项目：`agent_lifeRestart`。

原作信息不删除，但换到更合适的位置：

- 首页主介绍：当前项目是什么、怎么玩、怎么共创；
- GitHub 按钮：当前仓库；
- 左上角快捷入口：上方保留存档，下方打开当前仓库，两个按钮保持同等视觉尺寸并拉开距离；
- 右下角项目署名：`agent_lifeRestart / a [p → q] project`，入口指向 `ptoq.io`；
- 致谢页：当前项目说明、原作仓库、开源来源；
- `NOTICE` 和 [Credits](CREDITS.md)：完整保留上游来源和 license 信息。

这样玩家不会误以为还在原版页面里，原作也会得到清楚、体面的致谢。
